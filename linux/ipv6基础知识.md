# IPv6 基础知识

## 一、为什么需要 IPv6

IPv4 地址空间为 2^32(约 43 亿),已于 2011 年前后耗尽分配。IPv6 使用 128 位地址,地址空间为 2^128,理论上可容纳约 3.4×10^38 个地址,从根本上解决地址枯竭问题。

## 二、地址表示与结构

### 表示方法
- 128 位,写作 8 组 16 位十六进制数,冒号分隔:`2001:0db8:0000:0000:0000:ff00:0042:8329`
- 可省略前导零:`2001:db8:0:0:0:ff00:42:8329`
- 连续的全零组可用 `::` 缩写一次(只能出现一次):`2001:db8::ff00:42:8329`

### 地址结构(以 GUA 为例)
```
| 全局路由前缀(48位)| 子网ID(16位)| 接口ID(64位)|
```
一般 ISP 分配 /56 或 /48 给家庭用户,家庭内部每个子网用 /64。

## 三、地址分类

| 类型 | 前缀 | 作用 |
|---|---|---|
| 全局单播地址(GUA) | 2000::/3 | 全球可路由,相当于公网 IPv4 |
| 链路本地地址(Link-Local) | fe80::/10 | 仅本链路有效,每个接口自动生成,用于邻居发现等协议 |
| 唯一本地地址(ULA) | fc00::/7(实际用 fd00::/8) | 类似 IPv4 私网地址,不可全局路由 |
| 组播地址 | ff00::/8 | 替代 IPv4 广播,IPv6 没有广播概念 |
| 环回地址 | ::1 | 相当于 IPv4 的 127.0.0.1 |
| 未指定地址 | :: | 相当于 0.0.0.0 |

## 四、核心机制

### 1. 邻居发现协议(NDP)
替代 IPv4 的 ARP + ICMP 部分功能,基于 ICMPv6 实现:
- 路由器请求/通告(RS/RA):主机发现路由器和网络前缀
- 邻居请求/通告(NS/NA):地址解析(相当于 ARP)、重复地址检测(DAD)

### 2. 无状态地址自动配置(SLAAC)
主机收到路由器的 RA 通告后,用通告的前缀 + 自己生成的接口 ID(如 EUI-64 或随机数)拼出完整地址,无需 DHCP 服务器介入。

### 3. 隐私扩展(Privacy Extension / RFC 4941)
为防止用 MAC 地址推算出的接口 ID 被长期追踪,系统会定期生成随机接口 ID 作为对外临时地址,这是设备 IPv6 地址频繁变化的常见原因。

### 4. 前缀分配(DHCPv6-PD)
运营商给路由器分配一段前缀(如 /56),路由器再把 /64 子网分发给下游多个网段,实现层级化地址管理。

## 五、与 IPv4 的关键差异

| 方面 | IPv4 | IPv6 |
|---|---|---|
| 地址长度 | 32 位 | 128 位 |
| 地址解析 | ARP | NDP(基于 ICMPv6) |
| 广播 | 有 | 无,用组播替代 |
| NAT | 普遍使用 | 通常不需要(地址充足),端到端可达 |
| 分片 | 路由器可分片 | 只能由源主机分片,路由器不分片 |
| 头部 | 可变长,含校验和 | 固定 40 字节基本头,无校验和(依赖上层) |
| 配置方式 | 手动/DHCP | SLAAC / DHCPv6 / 静态,更灵活 |

## 六、报文头部特点

IPv6 基本头固定 40 字节,去掉了 IPv4 头部的校验和、分片相关字段,转发效率更高。额外功能通过"扩展头"(Extension Headers)链式添加,如逐跳选项、路由头、分片头、AH/ESP(IPsec)等。

## 七、过渡技术(双栈环境常见)

- **双栈(Dual Stack)**:同时运行 IPv4 和 IPv6,当前主流方式
- **隧道技术**:如 6to4、Teredo,让 IPv6 报文封装在 IPv4 网络中传输
- **NAT64/DNS64**:让纯 IPv6 网络访问 IPv4 资源
- **Happy Eyeballs**:双栈下,系统会同时尝试 IPv4/IPv6 连接,自动选用响应更快的一方,提升体验

## 八、安全相关要点

- IPv6 设计上内置支持 IPsec(但并非强制启用)
- 由于没有 NAT 的"天然屏蔽",每台设备可能有全球可达地址,**防火墙策略必须单独为 IPv6 配置**,不能依赖 IPv4 规则自动生效
- ND 协议本身缺乏认证机制,存在 NDP 欺骗等攻击面,大型网络中常需要 RA Guard、DHCPv6 Guard 等防护

# IPv6 网络划分规则

## 一、划分的基本单位与铁律

**核心规则:局域网子网固定用 /64,不可再分**

这是 IPv6 设计上的硬性要求,而非习惯:
- 接口 ID 占用后 64 位,SLAAC、DAD(重复地址检测)、隐私扩展等机制都建立在"64 位接口 ID 空间"这个假设上
- 唯一的例外是**点对点链路**(路由器之间互联),可以用 **/127**(RFC 6164 推荐),因为链路两端只有 2 个地址,不涉及 SLAAC

## 二、前缀长度与可用子网数的换算规则

给定上级分配的前缀长度 `P`,如果每个子网用 /64,可划分的子网数为:

```
子网数 = 2^(64 - P)
```

| 上级分配 | 可用 /64 子网数 |
|---|---|
| /48 | 2^16 = 65,536 个 |
| /52 | 2^12 = 4,096 个 |
| /56 | 2^8 = 256 个 |
| /60 | 2^4 = 16 个 |
| /62 | 2^2 = 4 个 |
| /64 | 1 个(无法再划分子网) |

**规则要点**:分配前缀每减少 4 位(十六进制一位),子网数扩大 16 倍——这也是为什么行业默认按"半字节"对齐分配(/48、/52、/56、/60,而非 /50、/58 这种奇怪长度)。

## 三、地址各段的角色划分规则

以 IPv6 地址的 8 组十六进制数为例,规则是从左到右按用途分层:

```
2001 : 0DB8 : 1234 : 5678 : 0000 : 0000 : 0000 : 0001
└──全局路由前缀──┘└子网ID┘└──────接口标识符 (64位)──────┘
```

- **全局路由前缀**:由 ISP/RIR 分配,决定你在互联网中的位置,不可自行更改
- **子网 ID**:你唯一能自由规划的部分,长度 = 64 − 你拿到的前缀长度
- **接口标识符**:固定 64 位,交给 SLAAC/DHCPv6 或手动配置,不参与"划分子网"的规划

## 四、子网 ID 分配规则(实操层面)

1. **按功能/部门/VLAN 划分**,一个 VLAN 对应一个子网 ID,一一对应,不要一个 VLAN 塞多个子网 ID 或反过来
2. **预留规则**:建议不要把子网 ID 顺序用满,常见做法:
   - `0` 留给核心/管理网络
   - 小编号(1-9)留给稳定的核心业务网段
   - 中间编号留给常规部门/楼层
   - 高编号或 `f` 结尾留给临时/测试网络
3. **对齐规则(为将来路由汇总做准备)**:如果规划了多层级结构(比如按楼栋→楼层→网段),子网 ID 的划分应按 2 的幂对齐分组,方便写汇总路由,例如:
   - 一栋楼 16 个子网:`0x00-0x0F` 可用一条 `/60` 汇总
   - 不对齐分配会导致后续无法用一条路由汇总,必须逐条写

## 五、什么情况不需要划分子网

- 拿到的前缀只有 /64(部分运营商对家庭用户如此),此时**无法再切分**,只能整个网络作为单一广播域使用,多 VLAN 需求需要向运营商申请更大前缀,否则只能所有 VLAN 共享同一前缀(退化成用 IPv4 隔离,IPv6 层面不隔离)
- 单一小型网络且未来无扩展需求,可以只申请/使用一个 /64,不必人为过度切分成多个更小的"名义子网"

## 六、点对点链路的特殊规则(/127)

路由器与路由器之间的互联链路,不涉及主机自动配置,规则不同于普通局域网:

- 推荐用 **/127**(仅 2 个地址,类似 IPv4 的 /30 用法),依据 RFC 6164
- 避免用 /64 做点对点链路 —— 曾出现过安全问题(Ping-Pong 攻击,利用 /64 链路上大量未使用地址进行 ICMPv6 时间超时攻击)
- 也可以用 /112 等做小范围管理网段,但业界主流仍是 /127

## 七、划分规则速查表

| 场景 | 规则 |
|---|---|
| 局域网子网(有主机自动配置需求) | 必须 /64 |
| 路由器间点对点链路 | 推荐 /127 |
| 从 /48 或 /56 分配子网 | 按半字节(4位)对齐,即 /52、/56、/60 |
| 需要未来路由汇总 | 子网 ID 分配需按 2 的幂分组对齐 |
| 只有单个 /64 可用 | 不可再分,VLAN 隔离需求需申请更大前缀 |
| DMZ / 安全隔离区 | 单独 /64,并配合独立防火墙规则,不与内网共享前缀 |

# IPv6 子网规划实践

## 一、基本原则:忘掉 IPv4 的"节省思维"

IPv4 时代大家习惯精打细算(/30、/29 抠着用),IPv6 完全不需要这样:

- **每个子网固定分配 /64**,不管这个子网只有 3 台设备还是 3000 台设备
- 原因:SLAAC、隐私扩展等机制都要求接口 ID 有 64 位空间,/64 是事实标准,分配更小的子网(如 /112、/127 点对点链路除外)会导致 SLAAC 失效
- 记住一句话:**规划 IPv6 子网是在规划"有多少个子网",而不是"每个子网要多少地址"**

## 二、常见分配层级

```
运营商(ISP)
   │  分配 /48 或 /56 给你(通过 DHCPv6-PD)
   ▼
你的路由器(网关)
   │  从 /56 中划分出若干 /64
   ▼
各个子网(VLAN):办公网、IoT网、访客网、DMZ...
```

**举例:假设 ISP 分配了 `2001:db8:1200::/56`**

/56 意味着你有 `56 → 64` 之间 8 位可用于子网划分,即 **2^8 = 256 个 /64 子网**可用。

## 三、实际划分示例

以 `2001:db8:1200::/56` 为例,规划家庭/小型办公网络:

| 子网用途 | 子网 ID(第7组十六进制的后2位) | 完整前缀 |
|---|---|---|
| 主网络(电脑/手机) | 00 | `2001:db8:1200:00::/64` |
| IoT 设备(智能家居) | 01 | `2001:db8:1200:01::/64` |
| 访客网络 | 02 | `2001:db8:1200:02::/64` |
| 服务器/NAS(DMZ) | 03 | `2001:db8:1200:03::/64` |
| 管理网络(路由器/交换机) | 0a(预留段) | `2001:db8:1200:0a::/64` |
| 预留/未来扩展 | 04~ff | 剩余 252 个 |

**理解地址结构中子网 ID 的位置:**
```
2001 : 0db8 : 1200 : 00xx : xxxx : xxxx : xxxx : xxxx
└──────前缀 /56───┘└子网┘└──────接口ID /64────────┘
              (第4组的高8位属于/56,低8位是子网可变部分)
```
如果是 /56,第 4 组(16 位)中,高 8 位固定,低 8 位由你自己分配子网号 —— 所以理论上 /56 给你 256 个子网。若拿到的是 /48,则整个第 4 组 16 位都可自由分配,即 65536 个子网。

## 四、划分建议(按场景)

**家庭网络(拿到 /56 或 /60)**
- 主网、IoT网、访客网三个 /64 基本够用
- 建议预留几个给未来的 VLAN(如智能音箱专网、摄像头专网)

**小型企业/多分支机构**
- 按部门/楼层/功能划分,如财务部、研发部、访客区各一个 /64
- 服务器区单独一个 /64,便于设置独立防火墙策略

**是否要考虑"二进制对齐"来分组?**
如果未来可能需要进一步做路由聚合(比如按楼层再细分),建议子网 ID 预留时按 4 的倍数或 16 的倍数分组,方便写路由汇总规则,类似 IPv4 里"打包成一条汇总路由"的思路。比如:
- `00-0f`(16个)分给一楼
- `10-1f`(16个)分给二楼
- 这样将来可以用一条 `2001:db8:1200:00::/60` 汇总一楼所有子网

## 五、常见误区提醒

| 误区 | 正确做法 |
|---|---|
| 想把 /64 再拆成更小子网(如 /112)给设备省地址 | 除点对点链路(常用 /127)外,不要拆分 /64,会破坏 SLAAC |
| 每个子网手动规划地址池,像 IPv4 一样精细管理 | 依赖 SLAAC/DHCPv6 自动管理即可,不需要手动分配单个地址 |
| 家用路由器拿到 /64 就想再往下分配子网 | ISP 若只给 /64(部分运营商是这样),无法再分子网,需向 ISP 申请更大前缀(/56 或 /60) |
| 认为 /48 太浪费,想申请更小的 | /48 或 /56 已是行业标准分配单位,不算浪费,直接用即可 |

## 六、实操检查:确认你拿到多大的前缀

在路由器状态页或用命令查看 WAN 口获得的 IPv6 信息,重点看:
- **分配的前缀长度**(Prefix Length):决定你有多少个 /64 可用(见上方公式 2^(64-前缀长度))
- 如果只拿到单个 /64 且无法申请更大前缀,那就只能做单一子网,无法内部再划分多个 VLAN 的独立 IPv6 段(这种情况下部分厂商设备的多 VLAN 会共享同一 IPv6 前缀,需注意)
